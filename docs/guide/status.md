# API status

IFLoom is **pre-release**. There is no stable API: names, shapes and defaults can change between commits, and nothing is published to npm yet. This page lists what you can reach today and what is planned to change.

## What you can import

**The front door** is `@ifloom/engine`, and it is the API. It exports everything a game needs — the types you declare a game with, data scenes and prose, conditions and effects, custom functions, the reducer, the loader, the runner, saves and the view — and everything it exports is documented in the [reference](/reference/game).

```ts
import { loadGame, startingState, apply, view, type DataScene, type StorylineDef } from '@ifloom/engine'
```

[First-party plugins](/plugins/) are their own packages, each with its own front door, such as `@ifloom/plugin-quests`, and so is the [base UI](/ui/), `@ifloom/ui`.

**Deep paths** such as `@ifloom/engine/scene.ts` still resolve, because the package ships its source files. They are not the API: anything reachable only that way is an internal, can change or vanish without notice, and is not documented. Code written against an earlier commit that used deep imports should switch to the front door; every name the docs used to deep-import is on it now.

## One clock: the turn

The engine used to date everything by the day, which only suited a game with a calendar. It now has one clock, the **turn**: `state.turn`, 0 in a new game. A turn is whatever the game says. The [`turn` effect](/reference/effects#turn) ends one, and the condition `{ turn: true }` with a range reads it. The day and the time of day have left the core for the [calendar plugin](/plugins/calendar), which says whether a turn is a period, a day or a week and ends turns as time passes; its `sleep` command moves its clock to the next morning, so in a game that sleeps, a turn is a day as before. At the end of a turn the counter goes up and `resets` are written, then `rules.turn`'s effects apply, then `rules.onTurn`, then each plugin's `turn` hook. The renames are in the table above; a save from before is carried forward on load.

## An optional world

A game no longer needs a place, a clock or an opening scene. [`loadGame`](/reference/loader)'s base needs only `id` and `title`; `introScene` is optional, and `validatePack` checks it only when given. The core has no places at all: a game that wants a map lists the [places plugin](/plugins/places), and one without it has no location, no exits and no one present. With no scene open and no plugin [stage](/reference/plugins#stage), the screen is the game's title with an empty body, and its buttons are plugins' then the game's own `actions`. See [Shapes of game](/guide/shapes) for a novel written that way.

## Planned work

- **Declared stats — done.** The engine assumes no stats at all. A game declares every [stat](/reference/stats) it keeps — label, start, range (with a ceiling that can move), visibility, bands, format, whether it is spent on things — and money and energy are ordinary declared stats like any other.
- **The runner — done.** One object a UI drives: [`createRunner`](/reference/runner) wraps `apply` with undo and redo (with barriers), a backlog, a command log that [`replay`](/reference/runner#replay)s to the same state, saving, loading and autosave. Everything but the log is off until the game turns it on.
- **Saves, rebuilt — done.** [Saves](/reference/saves) are snapshots with metadata for a load screen, in named slots, kept by a driver the game picks — `localStorage`, IndexedDB, memory or its own — with export and import, and the packs a save was made with. This replaces the earlier numbered slots and the synchronous key–value store. The format is at version 8; old saves are carried forward a step at a time: 4 → 5 moves the old clock into the calendar's state, `plugins.calendar`, 5 → 6 moves where the player was into the places plugin's, `plugins.places`, 6 → 7 adds `removed`, the declared entities removed in play, and 7 → 8 drops each storyline's `standing` and `rapport`.
- **View slices for plugins — done.** Each plugin adds its own slice at [`view.plugins`](/reference/view#plugins). Where the player is and the exits are the [places plugin](/plugins/places#the-view)'s slice, and who is in the room the [cast plugin](/plugins/cast#the-view)'s. The first game's `persona`, `web`, `hints` and `profiles` are gone.
- **A real front door — done.** Everything a game needs is exported from `@ifloom/engine`; deep imports are no longer needed.
- **Custom functions per game — done.** Custom conditions, effects, values and panels live on the game (`game.custom`), not in global registries, so two games never see each other's. Still to come: the loader reporting which pack each custom function came from, and when a mod replaces one.
- **Data scenes without a runtime — done.** A game lists data scenes beside hand-written ones and the engine renders them with its [default runtime](/reference/scenes#defaultruntime): prose from `game.prose`, rotating variants, once-per-turn choices.
- **Content as data — done.** No content is a function any more: locations, schedules, activities and stages are written in conditions, effects and prose blocks like data scenes, and the [loader](/reference/loader#the-checks) checks them the same way. A [custom function](/reference/custom) is the one way out to code.
- **Why is this greyed out? — done.** [`explain`](/reference/conditions#why-does-it-hold) walks a condition and says which part failed and what it read.
- **Plugins — done.** Code that adds a system to the engine, such as a quest list, a phone or a wardrobe. A [plugin](/reference/plugins) has its own state in the save, with versions and migrations, and its own conditions, effects, commands, prose values, hooks, view slice and content checks. Content calls them by name as it calls custom functions (`{ custom: 'quests/done' }`), or in short with the name as the only key (`{ 'quests/done': { quest: 'bakery' } }`). A plugin can answer other plugins' `queries` by name, and name the plugins it `cooperates` with, whose conditions and effects content may then use in a game without them. Plugins are composed when the game is built, never loaded while it runs.
- **First-party plugins — started.** The [calendar](/plugins/calendar) (`@ifloom/plugin-calendar`), [places](/plugins/places) (`@ifloom/plugin-places`), the [cast](/plugins/cast) (`@ifloom/plugin-cast`), [quests](/plugins/quests) (`@ifloom/plugin-quests`), the [wardrobe](/plugins/wardrobe) (`@ifloom/plugin-wardrobe`), [messages](/plugins/messages), [feed](/plugins/feed), [devices](/plugins/devices) and [debug](/plugins/debug) are separate packages, the engine as a peer dependency, none requiring another. Each says its player-facing lines through the [strings table](/reference/strings), so a game can reword them (`quests/notDoing`).
- **Devices — done.** The core parts a phone, a laptop or a notice board is built from have landed: [collections](/reference/collections) (a gallery, notes, a ledger), [notices](/reference/notices) (badges and toasts), [triggers](/reference/triggers) (something arrives the first time a condition holds), [inputs](/reference/inputs) (a typed name, an alarm time) and calls (a character's scene from anywhere, now the [cast plugin](/plugins/cast#calls)'s). The plugins have landed too: [devices](/plugins/devices) (`@ifloom/plugin-devices`), with apps declared as data; [messages](/plugins/messages) (`@ifloom/plugin-messages`), which arrive as scenes with replies as choices; and [feeds](/plugins/feed) (`@ifloom/plugin-feed`) of posts. The [phone bundle](/plugins/phone) (`@ifloom/phone`) wires all three together. Still to come: the swipe deck (cards dealt from a pool, with effects on accept and reject, for a dating app or a job board), planned for the extras library.
- **Player-facing words are the game's — done for the engine and the first-party plugins.** Every line the engine and the first-party plugins say to the player — refusals, input checks, button labels, save messages, the calendar's period and weekday names — comes from the [strings table](/reference/strings). A game, a pack or a translation mod rewords any of them by key. The [base UI](/ui/#words)'s own words, such as calling quests a journal, are in the same table under `ui.` keys. Not covered yet: full translation beyond swapping words, such as plurals and word order, and the labels on the debug panel's forms.
- **Mod runtime — done for data mods.** A player adds a [mod file](/reference/mods) to a built game, which keeps it in IndexedDB and loads its pack over the game's own at start-up; the base UI's [mod manager](/ui/components#modmanager) adds, turns off and removes them. A game opened from disk cannot read a mods folder itself, so the player hands it the files. Still to come: code mods, only when the player explicitly chooses to load them.
- **A base UI — done.** [`@ifloom/ui`](/ui/) draws the view in React with shadcn/ui and Tailwind CSS: `GameShell` for the whole screen, and every part exported for a game to rearrange, restyle through CSS variables, or extend with its own panels and plugin sections. A greyed-out button shows its reason on the button. It has the player's own screens too: the [wardrobe](/ui/components#wardrobepanel), the [inventory](/ui/components#inventory) with items to use, [inputs](/ui/components#inputfield), a [saves menu](/ui/components#savesmenu) with export and import, the [backlog](/ui/components#backlog), undo and redo, and the [mod manager](/ui/components#modmanager) in the [player's menu](/ui/components#gamemenu), each shown when the game turns it on. Its own words go through the strings table under `ui.` keys. It reads plugins' views by shape and depends on no plugin package.
- **A debugger — done.** The [debug plugin](/plugins/debug) (`@ifloom/plugin-debug`) sets stats (an entity's too, such as a character's friendship), variables, items, the scene, the turn, the calendar's clock and where the player is (each when the game has that plugin) by hand, through any lock, and the base UI draws a panel for it. It is left out of release builds. Its commands are the first to use [`ignoresLocks`](/reference/plugins#commands-outside-the-story).
- **A CLI — done.** [`@ifloom/cli`](/cli/) has `ifloom dev`, `ifloom build` (one HTML file, checked to open from disk, with the pictures inside it too if asked), `ifloom check`, `ifloom playtest` (plays the game unattended and writes down every screen and each turn's numbers) and `ifloom snapshot` (every scene in a few states, compared with the last run), and the Vite preset `@ifloom/cli/vite`.
- **Entities — done.** A game declares [kinds](/reference/entities) of thing it keeps several of — staff, dishes — and stats that belong to a kind (`StatDef.of`). Entities are declared or [created](/reference/effects#create) in play, [removed](/reference/effects#remove), run over with [`each`](/reference/effects#each), counted with [`{ count }`](/reference/conditions#count), and reached by every stat and variable effect and condition through `of`. The view and the base UI's [`EntityTable`](/ui/components#entitytable) show them. The loader checks kinds in conditions and in triggers' effects, but not yet in data scenes' or activities' effects.
- **Shapes of game — done.** One engine makes any of the three [shapes](/guide/shapes), each a buildable example with `npm run dev` and `npm run build`. [The Letter](/guide/shapes), in `examples/novel`, is a linear novel with no plugins, places, characters or clock, drawn with the base UI's [`READING_LAYOUT`](/ui/#layouts). [The Corner Café](/guide/shapes#a-management-game-the-corner-cafe), in `examples/cafe`, is a management game run a week at a time on entities, with its tables on the stage. Small Town's social shape is the core with the calendar, places and the cast, in the default layout. The last part to land: the base UI laid out by [parts](/ui/#layouts), each drawing nothing when the game has nothing for it, and an [`ifloom playtest`](/cli/#explorer) explorer that knows no plugin it needs — it finds the button that ends the turn by trying each, and presses it last.
- **The showcase game — started.** [Small Town](/guide/showcase), in `examples/showcase`: a first week with a phone, quests, a wardrobe, triggers and notices, an input, an item to use, saves and a backlog, a mod and pictures of its own, played by its tests. The examples in these docs come from its world. Still to come: pictures of its places, and a mod that patches a scene.
